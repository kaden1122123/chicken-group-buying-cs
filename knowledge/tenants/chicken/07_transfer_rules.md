# 人工介入條件（Human Handoff Rules）

## 核心理念

**AI 處理常見問題，真人處理複雜問題。**
當 AI 判斷無法處理時，目標是：
1. 讓用戶感受到「問題已被記錄，正在處理」
2. 將必要資訊完整交給 Hubert，不讓他浪費時間反覆確認
3. 避免 AI 胡亂回答造成更大問題

---

## 觸發方式：語意相近就觸發（Semantic Matching）

**原則：非精確關鍵字比對，而是使用 LLM 自然語言理解判斷語意相似度。**

當客戶表達的意思與以下 14 種情況「語意相近」時，即觸發 Human Handoff。
例如：
- 「要退款」→「退貨/退款」語意相近 ✅
- 「不訂了」→「取消訂單」語意相近 ✅
- 「便宜一点」→「折扣請求」語意相近 ✅

---

## 必須轉交真人的 14 種情況

當客戶屬於以下任何一種情況時，**立即轉交真人處理，不得自行判斷**：

### L1 — 必須立即通知 Hubert（高嚴重性）

| # | 觸發條件 | 語意範例 | Hubert 通知標題 |
|---|---------|---------|----------------|
| 1 | 客戶要求**退款** | 「要退款」、「錢退回來」、「退我錢」 | 【退貨/退款】 |
| 2 | 客戶要**取消已成立訂單** | 「不訂了」、「取消吧」、「可以取消嗎」 | 【取消訂單】 |
| 3 | 客戶**收單後想改天** | 「改到明天」、「想換日期」、「改一下時間」 | 【改天需求】 |
| 4 | 客戶**抱怨品質、配送或服務** | 「雞肉壞了」、「送來太慢」、「有問題」 | 【售後/客訴】 |
| 5 | 客戶**態度激動或有爭議** | 「叫你老闆來」、「不要AI」、「叫真人」 | 【客訴/爭議】 |
| 6 | 客戶明確說「我要跟**真人**說」「不要AI」 | 「我要跟人說」、「叫真人來」 | 【明確要求真人】 |

### L2 — 需真人確認（中嚴重性）

| # | 觸發條件 | 語意範例 | Hubert 通知標題 |
|---|---------|---------|----------------|
| 7 | 客戶要求**特殊折扣** | 「便宜一點」、「打了折」、「優惠一些」 | 【折扣請求】 |
| 8 | **地址不確定**是否在配送範圍 | 超出三鶯地區的地址 | 【配送範圍確認】 |
| 9 | 客戶要求**大量訂購或公司合作** | 「公司訂購」、「大量採購」、「合作」 | 【大批訂單/公司合作】 |
| 10 | **訂單金額異常**（超過 NT$3,000） | 單筆訂單 > $3000 | 【金額異常】 |

### L3 — 需真人處理（低嚴重性）

| # | 觸發條件 | 語意範例 | Hubert 通知標題 |
|---|---------|---------|----------------|
| 11 | **付款截圖不清楚或金額不符** | 截圖金額與訂單不符 | 【付款異常】 |
| 12 | **LINE Pay code 過期或付款失敗** | 「LINE Pay 失敗」、「付不了」 | 【LINE Pay 付款失敗】 |
| 13 | **開團日期不確定** | 「這週有開嗎」、「什麼時候開團」 | 【開團日期確認】 |
| 14 | 客戶**14:00 後想追加雞肉** 或 **18:00 後想變更小菜/時段** | 「再追加」、「加一盒」、「改一下小菜」 | 【截單後變更】 |

## Human Handoff 安全流程（修訂版）

**重要：轉人工通知的前提是也在 CSV 檔案內有進行資訊登入+備註。**

```
客戶說出 14 種條件之一（語意相近就觸發）
       │
       ▼
┌─────────────────────────────────────────┐
│ Step 1: 立即寫入 CSV（這是安全閘）       │
│   - order_id = "PENDING"（暫掛訂單）   │
│   - order_status = "pending_handoff"   │
│   - handoff_type = [對應類型]           │
│   - customer_notes = [客戶原始訊息]     │
│   - staff_notes = [問題摘要]             │
│   - handoff_logged_at = [時間戳]        │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│ Step 2: 回覆客戶制式話術                 │
│ 「目前老闆再忙，後續會再回覆您，          │
│  請留意 LINE 通知，謝謝！」              │
└──────────────┬──────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────┐
│ Step 3: 通知 Hubert（LINE Push）         │
│   - 附上 CSV 中該筆 order_id            │
│   - Hubert 可直接回 CSV 查看完整上下文   │
│   - 通知內容包含：案件類型/用戶資料/     │
│     問題摘要/AI已回覆內容/發生時間      │
└──────────────────────────────────────────┘
```

## 轉真人時的標準客戶回覆

觸發以上任一條件時，回覆客戶統一的制式話術：

> 「目前老闆再忙，後續會再回覆您，請留意 LINE 通知，謝謝！」

**注意：** 回覆要自然，不要讓客戶感覺被踢來踢去。

## 禁止事項

- ❌ AI 不得自行承諾退貨、補償、折扣
- ❌ AI 不得透露 Hubert 的個人聯繫方式（LINE ID、Willy0221 等）給用戶
- ❌ AI 不得在未通知 Hubert 的情況下結束可能需要處理的對話
- ❌ 通知內容不得包含用戶對話的全部歷史（隱私考量，只傳摘要）
- ❌ 遇到品項細節問題時，不得自行回答 → 統一回覆「拍謝！稍後由老闆親自回覆您。」
- ❌ 不得在未寫入 CSV 的情況下直接通知 Hubert（順序不能顛倒）

## AI 處理邏輯（Pseudo-code）

```
IF 客戶說任何與「退款/退貨」語意相近的話
   → 立即寫入 CSV（handoff_type=refund_request）
   → 回覆制式話術
   → 通知 Hubert【退貨/退款】

IF 客戶說任何與「取消訂單」語意相近的話
   → 立即寫入 CSV（handoff_type=cancel_request）
   → 回覆制式話術
   → 通知 Hubert【取消訂單】

IF 客戶連續 3 次詢問，AI 知識庫均無法回答
   → 立即寫入 CSV（handoff_type=unanswered_questions）
   → 回覆制式話術
   → 通知 Hubert，附上對話摘要

IF 客戶說任何與「跟真人說/不要AI」語意相近的話
   → 回覆「了解！我已通知管理員，將由專人與您聯繫。請稍候 🙏」
   → 立即寫入 CSV（handoff_type=explicit_request）
   → 通知 Hubert【明確要求真人】

IF 配送地址超出已知範圍
   → 回覆「您的地址是否能配送需由客服進一步確認。已協助轉交人工處理，將盡快回覆您。」
   → 立即寫入 CSV（handoff_type=delivery_confirm_needed）
   → 通知 Hubert【配送範圍確認】

IF 其他任何知識庫未記載的問題
   → 回覆「拍謝！稍後由老闆親自回覆您。」
   → 立即寫入 CSV（handoff_type=product_inquiry）
   → 通知 Hubert
```

## 語意觸發實作原則

1. **使用 LLM 判斷**：不依賴精確關鍵字，而是讓 AI 理解客戶說的「是什麼意思」
2. **模糊地帶從寬**：當不確定是否觸發時，傾向於轉真人（安全第一）
3. **每次轉人都要寫 CSV**：順序是固定的，不能跳過
4. **通知中附 order_id**：讓 Hubert 能快速查詢完整上下文
