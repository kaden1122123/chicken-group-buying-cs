## 一、專案定位（必讀背景）

**這個專案的 `src/` 不是 production runtime！** 真正的 production 是 `~/.openclaw/agents/external-user/` 的 OpenClaw agent。

`src/` 的真實角色：
1. ✅ 規格 / 設計的程式化版本（驗證邏輯正確性）
2. ✅ 單元測試對象（rules / handoff / states / security / date / config / whitelist / integration / api-server / dashboard-server 共 10 套測試）
3. ❌ 不被 Cloudflare Worker 呼叫執行（Worker 直送 OpenClaw agent）

**但 `docs/SOP.md`、`docs/INDEX.md`、`SPEC.md` 過去都把 `src/` 描述成 production runtime。** 這個文檔 vs 實情的落差，會誤導接手的人。

下列問題標注：
- ⚠️ **[Production]**：在 production 也會發生
- 🔧 **[Code-only]**：只在 src/ 內部有問題，不影響 production 行為

## 三、發現問題（按嚴重度）

### 🔴 P0 — 嚴重，影響 production 行為

#### P0-1. ⚠️ [Production] `addressRule.js` 對「超出配送範圍」說謊
- **位置**：`src/rules/addressRule.js`、`src/index.js` AWAITING_INFO case
- **問題**：當客戶輸入「大溪區三元街」時，addressRule 會回傳「已協助轉交人工處理」，但實際上沒有觸發 handoff，只是回到 REASK_INFO 等下一個訊息。
- **影響**：客戶會被卡住，覺得 Bot 在裝忙；Hubert 也不會收到 LINE 通知。
- **證據**：`tests/rules.test.js` 只驗證 errorMessage 文字，沒驗證 handoff 是否被觸發。`src/index.js` 在 AWAITING_INFO 收到 `validation_failed` 時直接 `transition('field_received', { validationFailed: true })` → 切到 REASK_INFO，**沒有呼叫 handleHandoff**。
- **修整**：addressRule 對「超出配送範圍」要 return 不同的 action（例：`{ valid: false, action: 'handoff_needed', reason: 'out_of_range' }`），讓 index.js 走 handleHandoff 路徑；或 index.js 額外檢查 addressRule 結果後呼叫 handleHandoff。

#### P0-2. ⚠️ [Production] `handoff.js` 的 customer_reply 沒讀 config
- **位置**：`src/states/handoff.js` 第 76 行附近
- **問題**：寫死「目前老闆再忙，後續會再回覆您，請留意 LINE 通知，謝謝！」。但 `config/tenants/chicken.yaml` 的 `handoff.customer_reply` 是「感謝您的提問！您的問題已轉交給老闆處理，將儘快回覆您，請留意 LINE 通知，謝謝！🐔」。**設定檔的內容被忽略**。
- **影響**：Hubert 改設定檔但客戶看不到變更；不同 tenant 切換時訊息無法客製。
- **修整**：從 config 讀取 `handoff.customer_reply`（先把 config.js 加 `getHandoffCustomerReply()` 介面）。

#### P0-3. 🔧 [Code-only] `stateMachine.js` 的 `transition` 覆蓋已驗證的 trimmed 資料
- **位置**：`src/index.js` 第 96-104 行 + `src/states/stateMachine.js` `transition` 函數
- **問題**：`awaitingInfo.handleAwaitingInfo` 內已 `value.trim()` 並存到 `updatedOrderData.address`。但 `index.js` 後續 `transition(userId, 'field_received', { fieldName: context.awaitingField, value: cleanMessage, ... })` 用 `cleanMessage`（未 trim）覆蓋一次，CSV 寫入時有前後空白。
- **影響**：CSV 中 `address` 欄位會有殘留空白，dashboard 顯示會亂掉；handoff 通知也帶有空白地址。
- **修整**：傳 `data.fieldValue`（已 trim + 驗證後的值）給 transition，或 `transition` 不主動覆蓋（只更新 state/context）。

#### P0-4. ⚠️ [Production] `scripts/admin.html` 不存在
- **位置**：`scripts/dashboard-server.js` 第 28、146 行
- **問題**：`const ADMIN_HTML = path.join(ROOT, 'scripts', 'admin.html')`，GET `/admin` 路由會 `fs.readFileSync` 讀它，**但這個檔案不存在**。訪問會 return 500。
- **影響**：`/admin` 是「編輯 open_dates / ignored_keywords 的管理後台」，這個核心功能壞掉。`PHASE1_PROGRESS.md` 與 `SESSION_BACKGROUND.md` 都說「管理後台可用」，但實測會 500。
- **修整**：建立 `scripts/admin.html`（vanilla JS + fetch `/api/data` + `/api/config`）。

#### P0-5. 🔧 [Code-only] `cognee_import.py` 是 placeholder
- **位置**：`scripts/cognee_import.py`
- **問題**：`import cogenee`（拼錯，套件叫 cognee）— 整個 import 都會失敗。函式內只有 print 沒真的寫入。`MEMORY.md` 寫「Cognee 知識圖譜 ✅」，但實際上是 placeholder。
- **影響**：SOP.md §七 寫的「知識庫訓練」流程不存在。
- **修整**：要嘛真的接 cognee（需要實際的 API），要嘛刪除 `cognee_import.py` 並更新 MEMORY.md（本輪先標記，下輪處理）。

#### P1-2. addressRule.js 對配送區域用 hardcode
- **位置**：`src/rules/addressRule.js` 的 `ALLOWED_KEYWORDS`、`DENIED_KEYWORDS`
- **問題**：hardcode `['三峽', '北大特區', '老街', '介壽', '安溪', '鶯歌']`。但 `config/tenants/chicken.yaml` 的 `delivery.areas.allowed/denied` 是「三鶯生活圈」這種抽象描述。`knowledge/tenants/chicken/04_delivery.md` 才是具體清單。

#### P1-3. menuRule.parseItems 兩個 regex pattern 會產生重複 items
- **位置**：`src/rules/menuRule.js` `parseItems` 函數
- **問題**：第一個 pattern 抓「鹽水雞 x2」，第二個 pattern 也會對「鹽水雞 x2」匹配（unit 可選）。兩個 pattern 都會 append item，結果重複。
- **影響**：客戶輸入「鹽水雞x2」會被計算成 4 盒。
- **修整**：兩個 pattern 互斥（用 lookahead），或只跑一個。

#### P1-4. paymentRule.PAYMENT_METHODS 字典有兩個 key 體系混用
- **位置**：`src/rules/paymentRule.js`
- **問題**：key 一部分是原始字串（「現金」、「轉帳」、「街口」、「LINE Pay」），另一部分是去空白後小寫（「现金」、「linepay」）。對「LinEPay」、「line pay」、「line-pay」會行為不一致。
- **影響**：客戶輸入變體可能驗證失敗。
- **修整**：全部 key 用去空白 + 小寫 + 去標點的 normalized 形式。

#### P1-5. package.json test script 只列 4 套
- **位置**：`package.json` 第 9-12 行
- **問題**：`scripts.test` 只跑 4 套（rules/handoff/security/states），沒列 date、config、whitelist、integration、api-server、dashboard-server。
- **影響**：`npm test` 只驗證 1/3 的測試，可能誤判健康度。
- **修整**：改用 `node tests/*.test.js` 或寫個 `tests/run-all.sh`。

#### P1-6. CSV 欄位 `community` 在 awaitingInfo 流程中沒被收集
- **位置**：`src/states/awaitingInfo.js` FIELD_ORDER + `knowledge/02_order_flow.md` 「10 步驟」
- **問題**：knowledge 寫「社區或公司名稱」是第 6 個欄位，但 awaitingInfo 的 FIELD_ORDER 只收 7 個欄位（address, name, phone, menu, date, timeSlot, paymentMethod），沒有 community。
- **影響**：客戶填的社區名會被當成地址一部分（可能觸發 addressRule 拒絕）。
- **修整**：FIELD_ORDER 加 `community`，或在 addressRule 後追問「是否有社區/公司名稱」。

#### P1-7. docs/INDEX.md 列 8 套測試，但實際有 10 套

- **問題**：INDEX.md 沒列 `api-server.test.js` 與 `dashboard-server-test.js`。SESSION_BACKGROUND.md 又寫「9 套」。

#### P1-8. dashboard-server.js 寫死 js-yaml，沒 fallback
- **位置**：`scripts/dashboard-server.js` 第 13 行
- **問題**：`const yaml = require('js-yaml');` 直接 require。但專案沒 `node_modules` 目錄。`src/config.js` 有 fallback parser，但 dashboard-server 沒有。

#### P1-9. dashboard-server.js 寫入 tenant yaml 會覆蓋整個檔案
