---

## 核心理念

**AI 處理常見問題，真人處理複雜問題。**

當 AI 判斷無法處理時，目標是：
1. 讓用戶感受到「問題已被記錄，正在處理」
2. 將必要資訊完整交給 Hubert，不讓他浪費時間反覆確認
3. 避免 AI 胡亂回答造成更大問題

---

## 觸發方式：語意相近就觸發（Semantic Matching）

**原則：非精確關鍵字比對，而是使用 LLM 自然語言理解判斷語意相似度。**

當客戶表達的意思與 14 種情況「語意相近」時，即觸發 Human Handoff。

## 安全流程架構（修訂版）

**重要：轉人工通知的前提是也在 CSV 檔案內有進行資訊登入+備註。**

```
用戶訊息
    │
    ▼
┌─────────────────────────┐
│  AI 語意判斷模組         │
│  （Semantic Matching）   │
└────────┬────────────────┘
         │
    ┌────┴────┐
    │         │
  [可處理]  [無法處理/語意觸發]
    │         │
    ▼         ▼
  正常回覆   觸發 Handoff
             │
             ▼
    ┌────────────────────────────┐
    │  Step 1: 立即寫入 CSV      │  ← 安全閘
    │  - order_id = "PENDING"   │
    │  - handoff_type           │
    │  - customer_notes         │
    │  - staff_notes            │
    │  - handoff_logged_at      │
    └──────────────┬─────────────┘
                   │
                   ▼
    ┌────────────────────────────┐
    │  Step 2: 回覆客戶制式話術  │
    │  「目前老闆再忙，後續會再   │
    │   回覆您，請留意 LINE 通知，│
    │   謝謝！」                  │
    └──────────────┬─────────────┘
                   │
                   ▼
    ┌────────────────────────────┐
    │  Step 3: LINE Push 通知    │
    │  目標：Hubert             │
    │  附：order_id（供查詢）    │
    └──────────────┬─────────────┘
                   │
                   ▼
            Hubert 處理
                   │
                   ▼
    ┌────────────────────────────┐
    │  Hubert 填寫：            │
    │  - handoff_resolved_at    │
    │  - handoff_resolved_by    │
    └────────────────────────────┘
```

## 通知內容格式

### LINE 通知（主要）

當觸發 Handoff 時，AI 主動發送 LINE 訊息給 Hubert：

```
🔔 【AI 客服轉報通知】
═══════════════════════════

📋 案件類型：[配送問題 / 售後問題 / 金額問題 / 特殊需求]
👤 用戶：{LINE名稱}
📞 電話：{電話號碼，若有}
📍 地址：{地址，若有}
📝 問題摘要：
{AI 擷取的關鍵對話}

📎 CSV 查詢：
order_id: {PENDING-時間戳}

═══════════════════════════
⏰ 發生時間：{時間}
🤖 已嘗試：{AI 嘗試回覆的內容}
```

### Gmail 通知（備援）

當 LINE 通知失敗時，改用 Gmail 寄送：

```
Subject：[AI客服轉報] {用戶名稱} - {案件類型}

Body：
案件類型：{分類}
用戶 LINE 名稱：{名稱}
電話：{電話}
地址：{地址}
問題摘要：
{完整對話摘要}

--
此為系統自動發送，請勿直接回覆。
```

## 各觸發情境的標準作業流程

### L1-1：售後服務（退貨/客訴）

```
用戶：商品壞了/有問題（語意判斷）
    ↓
AI 立即寫入 CSV（handoff_type=complaint）
    ↓
AI 安撫：「感謝您反映！我們非常重視您的意見。」（制式回覆）
    ↓
AI 同時背景通知 Hubert（不讓用戶知道有通知）
    ↓
AI 結尾：「已通知管理員，將盡快與您聯繫處理。🙇」
```

**Hubert 收到通知後的動作：**
1. 查看 CSV 中該筆訂單（用 order_id 查詢）
2. 查看商品問題（可要求用戶拍照）
3. 決定處理方式（退貨/補償/解釋）
4. 回覆用戶 + 更新 CSV（handoff_resolved_at/by）

---

### L1-2：明確要求真人

```
用戶：我要跟真人說/不要AI（語意判斷）
    ↓
AI 立即寫入 CSV（handoff_type=explicit_request）
    ↓
AI：「了解！我已通知管理員，將由專人與您聯繫。請稍候 🙏」
    ↓
背景通知 Hubert（附 LINE 名稱 + 對話摘要 + order_id）
```

---

### L2-1：配送地址超出範圍

```
用戶：（提出非三峽/鶯歌地區地址）
    ↓
AI 立即寫入 CSV（handoff_type=delivery_confirm_needed）
    ↓
AI：「感謝您的提問！您的地址是否能配送，需由客服進一步確認。已協助轉交人工處理，將盡快回覆您。」
    ↓
背景通知 Hubert（附地址 + 用戶 LINE 名稱 + order_id）
    ↓
Hubert 確認後回覆用戶
```

---

### L3-1：品項細節問題

```
用戶：（詢問知識庫未記載的品項問題）
    ↓
AI 立即寫入 CSV（handoff_type=product_inquiry）
    ↓
AI：「拍謝！這個問題我需要由老闆親自回覆您，已記錄您的問題，將盡快與您聯繫。🙇」
    ↓
背景通知 Hubert（附問題 + 用戶 LINE 名稱 + order_id）
```

## 禁止事項

- ❌ AI 不得自行承諾退貨、補償、折扣
- ❌ AI 不得透露 Hubert 的個人聯繫方式（LINE ID 等）給用戶
- ❌ AI 不得在未通知 Hubert 的情況下結束可能需要處理的對話
- ❌ 通知內容不得包含用戶對話的全部歷史（隱私考量，只傳摘要）
- ❌ 不得在未寫入 CSV 的情況下直接通知 Hubert（順序不能顛倒）
