## 設計決策

### 為什麼 notifier.js 用 `channels` option 而不是新 function？

- 維持向後相容：既有 `notifyHubert(msg, opts)` 呼叫不需改
- 簡單：1 個 option 陣列決定走哪些 channel
- 易測試：明確的 contract

### 為什麼 email throttle 是全域變數而非 per-call？

- 連續 `notifyHubert()` 呼叫（5s 內 3 封）會被 Gmail 標記為 spam
- 全域變數保證整個 process 內所有 notifyHubert 都遵守節流
- test 環境可手動重置 `_lastEmailSentAt = 0`

### 為什麼 `getUpcomingOpenDates` 不傳 days 而用 weeks？

- 14 天 = 「最近兩週」的 Hubert 用語直接對應 `weeks=2`
- 未來如果要 30 天，改 `weeks=4.3` 比較怪，不如加 `days` 參數擴充
- 計算時用 `setDate(getDate() + weeks * 7)` 處理 timezone +08:00

### 為什麼 sanitize 黑名單而不是白名單？

- 白名單：「只允許中文 / 英文 / 標點」會誤擋合法訊息
- 黑名單：「`Exec failed` / `TypeError` / stack trace」較精準
- 但黑名單可能漏抓新模式 — 若客戶回報仍有作業訊息，加 pattern

### 為什麼 `flexReply` 要保留 reference equality？

- 既有測試 `assert.strictEqual(f1.contents, flexContents)` 期待 reference
- 若 spread 會破壞 reference equality
- 用 `needsNewContents` flag：需要 sanitize 時才 spread，否則保留原 reference
