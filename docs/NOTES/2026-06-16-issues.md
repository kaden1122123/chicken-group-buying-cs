## 問題分析

### 1. Quick Reply 沒顯示

**可能原因**：
- LLM 沒有把 quick reply 結構放進 LINE 訊息
- prompt 描述 quick reply 是用文字描述（`{"type":"text","text":"...","quickReply":{...}}`），但 LLM 把它當作範例輸出成純文字
- LLM 輸出的是純文字回覆（不是 LINE 訊息物件）
- 雞味客服的 prompt 設計可能根本不會讓 LLM 輸出 LINE 結構化訊息

**應檢查**：
- OpenClaw agent 的實際 prompt 機制是什麼
- 雞味 prompt 怎麼引導 LLM 輸出「LINE 訊息物件」而非「對話文字」
- 是否需要工具（tool）讓 LLM 標記訊息為「含 quick reply」

### 2. CSV 沒寫入

**可能原因**：
- 因為 quick reply 沒顯示 → 客戶沒按按鈕 → 沒有 postback → 沒有觸發 API
- 連鎖效應：quick reply 失敗 → postback 失敗 → API 沒被呼叫 → CSV 沒寫

**預期**：客戶按「確認訂購」按鈕 → LINE 發 postback → Worker 接收 → 呼叫 API → 寫 CSV

### 3. API-server 沒測試過

**可能原因**：
- OpenClaw exec 環境無法保持 background 進程（每次 exec 結束都 kill child）
- 需要在 SSH session 內啟動
- Hubert 沒啟動 api-server，所以 Worker 打 API 會失敗

**測試建議**：
```bash
# 在 SSH 內執行
cd /home/clawuser/openclaw-workspace/others/chicken-group-buying-customer-service
API_USERNAME=api-user API_PASSWORD=chicke…9k2x PORT=3001 node scripts/api-server.js &

# 然後測試
curl http://localhost:3001/api/health
```

## 整體檢討

### 架構問題
- **LLM 直接生成 LINE 訊息結構**這個假設可能不成立
- OpenClaw 可能把 LLM 輸出視為純文字，自動包成 LINE 文字訊息
- 要讓 LLM 影響訊息結構（如 quick reply），可能需要：
  - Tool calling 機制（讓 LLM 呼叫 tool 產生結構化訊息）
  - 或在 prompt 中用特殊語法標記（如 `:::quick_reply:::`）
  - 或完全不靠 LLM，用 LINE 的 Imagemap / Flex Message 模板

### 流程問題
- 新流程設計假設「LLM 會主動輸出 quick reply」 — 但實測失敗
- 顯示 LLM 並不總是按 prompt 指示
- 需要更可靠的觸發機制

### 監聽式 vs 主動觸發
- 我們放棄了「監聽式」改成「主動觸發」
- 但主動觸發的關鍵點（quick reply）沒生效
- 所以等於「兩種方式都沒成功」

## 新的可能方向

### 方向 A：完全不用 LLM 處理訂單
- LLM 只負責 FAQ、菜單查詢
- 訂單流程由 LINE Bot 的 Rich Menu / Quick Reply 直接驅動
- 客戶點 Rich Menu 的「我要訂購」→ 進固定流程 → 最後一鍵送出
- 缺點：流程僵硬，不能自然對話

### 方向 B：LLM 對話 + LINE 結構化訊息分開
- LLM 對話輸出純文字（規劃訂單）
- 客戶說「確認訂購」時，OpenClaw 觸發 Worker，Worker 自動送出 quick reply
- 缺點：LLM 不主動觸發 quick reply

### 方向 C：使用 OpenClaw tool calling
- 把 `sendLineQuickReply` 註冊為 OpenClaw tool
- LLM 在對話中主動呼叫 tool，產生結構化訊息
- 這需要改 OpenClaw 設定（複雜）

### 方向 D：特殊 prompt 標記
- LLM 在對話結尾加 `:::CONFIRM:::` 標記
- 訊息路由層（OpenClaw / Worker）偵測標記，自動加 quick reply
- 缺點：依賴 LLM 準確加上標記

### 方向 E：完全手動 trigger
- 客戶在 LINE 收到訂單摘要後，**手動**輸入「確認」
- 訊息路由層（Worker）偵測到，自動呼叫 API
- 缺點：用戶要打字
