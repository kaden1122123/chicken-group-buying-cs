## 實作方案比較

### 方案 A：純 Prompt（最簡單）

**做法：** 將所有知識直接寫進 Agent Prompt

**優點：**
- 實作簡單，無需額外技術
- 讀取速度快（無向量搜尋延遲）

**缺點：**
- Prompt 長度有限（約 8K-32K tokens，看模型）
- 知識更新需要改 Prompt
- 無法做自然語言搜尋

**適用情境：** 知識量少（< 1000 行）、不常更新

---

### 方案 B：Cognee RAG（推薦）

**做法：** 使用 Cognee 知識圖譜系統，結合向量搜尋與圖譜檢索

**優點：**
- 可擴充大量知識
- 自然語言搜尋能力強
- 知識更新只須新增文字，無需改 Prompt
- Hubert 可自行新增內容

**缺點：**
- 需要部署 Cognee（已有現成環境）
- 回應速度稍慢（向量搜尋 + LLM 生成）
- 實作複雜度中等

**適用情境：** 知識量大、需要長期維護

---

### 方案 C：結合方案（Prompt + RAG）

**做法：**
- Prompt 放「基本規則」與「回答範本」
- RAG 放「詳細商品資訊」與「動態內容」

**優點：**
- 結合兩者優點
- 基本問題快答，複雜問題 RAG

**缺點：**
- 實作複雜度最高

---

## 建議方案

**MVP（初期）：** 方案 A（純 Prompt）
- 簡單快速，可以先上線
- Hubert 整理完商品資訊後直接使用

**未來擴充：** 方案 B（Cognee RAG）
- 等系統穩定後再升級
- Hubert 已有 Cognee 環境，可以直接使用
